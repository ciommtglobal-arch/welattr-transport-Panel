# MMT Connect CIO — isolated Render review

This is a disabled-by-default, read-only candidate. It does not change the database, use a provider model, run a worker, start Gmail/UETS, or sign or send anything. The existing React routes and unrelated modules are preserved. The new corporate-domain routes call the same-origin Render Node API; the legacy Clerk proxy is not used for corporate login.

## Verify before enabling

- Verify the **production** Clerk tenant, first-party domain and CORS for `https://panel.mmtglobal.com.tr`, and the genuine founder subject. The normal Clerk session token (not a standalone custom JWT template) must carry the configured `aud` alongside verified `iss`, `azp`, `sub` and `sid`, with RS256 and a lifetime of at most five minutes. Do not reuse development accounts or proxy credentials through the test service. Plan for session revocation latency (bounded by token expiry) and key rotation; verify both before enabling.
- Rendering requires `VITE_MMT_CIO_CLERK_PUBLISHABLE_KEY` from that production instance at build time; this is a public identifier. The server needs `MMT_CIO_CLERK_ISSUER`, `MMT_CIO_CLERK_AUDIENCE`, `MMT_CIO_CLERK_JWT_PUBLIC_KEY` (issuer's public RSA verification key), `MMT_FOUNDER_REVIEWER_CLERK_USER_ID`, and the verified `MMT_CIO_BUSINESS_PROFILE_ID`. `MMT_CIO_READS_ENABLED` stays unset until verified.
- The database URL `MMT_CIO_READ_DATABASE_URL` must use a preexisting least-privilege SELECT-only role, TLS, and exactly the independently verified `MMT_CIO_EXPECTED_DATABASE_HOST` and `MMT_CIO_EXPECTED_DATABASE_NAME`. Do not use a general application DSN. Verify the needed tables, role permissions and business owner relationship without migrating. The runtime verifies that relationship before opening any source.
- `memory_store` and `founder_follow_up_versions` have owner but not tenant columns. A board file has neither. If the existing sources cannot be verified as exclusive to this exact owner and business profile, leave `MMT_CIO_OWNER_ONLY_SOURCES_VERIFIED` unset; the three data endpoints will stay unavailable. Do not copy or commit the raw board. Only a privately supplied, owner-readable regular file at `/etc/secrets/mmt-cio-task-board.md` is accepted. If Render cannot provide the required permissions, this source remains unavailable. The Markdown projection deliberately excludes titles, links and all free text; corporate and memory rows exclude full events and payloads.
- Do not merge until the same candidate commit passes the locked production build, signed-in founder and denied-session checks, and secret/data exposure review. Test actual production Clerk and data scope only in a separately authorized non-live verification environment. Do not deploy this branch by itself.

Local negative/fail-closed and synthetic projection tests: `node --test production/cio-routes.test.cjs`.
